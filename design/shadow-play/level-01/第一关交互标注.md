# 第一幕 · 小兔摘月｜设计交付 v1

本轮交付为静态视觉设计与交互规格，供风格评审；未开发游戏。以三态总览及单屏稿为视觉参考，以本文为交互规则。生成画面不作为精确碰撞坐标或可直接使用的切图。

## 画面状态

| 状态 | 可见变化 | 用户可做什么 | 状态出口 |
| --- | --- | --- | --- |
| 初始 | 兔影较小，月亮未接触；灯把手亮环和向右箭头 | 单指拖动灯；点击重来或提示 | 开始拖动进入操作态 |
| 操作 | 灯和底座一起沿轨道右移；实体皮影不变，兔影放大；接近时月亮边缘变亮 | 可向左或向右反复调整 | 手部投影接触目标连续 300ms，进入成功态 |
| 成功 | 灯轨锁定；触点泛金光，月亮呼吸发光；出现“好戏，成了！” | 动画结束后点击下一幕或再演一次 | 下一幕进入第二关；再演一次恢复初始 |

初始文案：“把灯推近，小兔的影子会变大。”
接近文案：“快碰到月亮了”。只在手与目标距离足够近时出现，不是开始拖动就显示。
成功文案：“今晚的月亮，被你摘下来了。”

## 操作与热区

- 灯与底座是一个整体；拖动灯体或圆把手均可抓取。触摸热区至少 48×48 CSS px，沿轨道限制移动，绝不越过木偶。
- 手指离开轨道仍维持当前拖动，直到抬起或触摸取消；不能让页面滚动打断灯的操作。
- 实体皮影、关节、月亮和幕布均不可拖动。本关没有手臂旋转、双指手势或第二种道具。
- 重来：立即恢复灯距和全部提示，不弹确认框。提示：在灯把手周围播放一次右移示意并显示原教学文案，不自动完成关卡。
- 页面失焦或触摸取消：结束拖动，保留灯位置，不自动通关；恢复后重新累计接触时长。
- 无倒计时、失败扣分、体力、登录或网络依赖。首关建议体验时长 15～30 秒。

## 光学关系与判定

操作区是“灯—木偶—影幕”的侧向示意，角色为便于辨认而采用斜视展示，不当作严格正侧面工程图。实体与投影必须使用同一姿态。

舞台上只有一个兔影。灯靠近木偶时，投影按固定光轴中心等比放大；不能只拉长手臂，不能靠移动月亮伪造过关。每张稿中的月亮位置、木偶大小、木偶姿态必须固定。

原型采用 z幕=1、z木偶=0.65、z灯∈[0,0.45]，倍率 m=(1-z灯)/(0.65-z灯)。根据美术资产实际手部位置，把月亮放在可触达轨迹上，再校准初始缩放与光轴位置。图中坐标是构图参考，不取代这一规则。

仅手掌/指尖投影参与判定，耳朵或身体不能触发。建议目标判定边界扩展约 12 CSS px，实际试玩后调整。持续接触 300ms 成功；未达到时离开目标，计时清零。

## 成功反馈时间轴

| 时间 | 画面与交互 |
| --- | --- |
| 0～0.3 秒 | 接触光环逐渐亮起，满足持续接触后锁定灯轨 |
| 0.3～1.0 秒 | 月亮产生柔和暖金光晕，少量微光从手心升起 |
| 1.0～2.2 秒 | 月亮一次轻微呼吸发光，画面停留欣赏；保持角色姿态和月亮位置 |
| 2.2～3.0 秒 | 成功文案与两个按钮淡入，开放点击 |

无需声音也能读懂成功。若后续使用音效，遵守平台音频能力与用户静音设置。

## 布局与适配

本次总览由三张等宽竖屏组成。生成稿比例约 1:2，为视觉评审尺寸。落地基准为 390×844 CSS px，额外高度优先用于顶部、底部安全区及舞台留白，不能直接非等比拉伸整图。

顶部预留约 48px，标题目标约 86px，舞台约 418px，引导约 44px，操作区约 164px，其余用于底部操作和安全区。平台顶部占用与底部手势区域以小红书容器实际尺寸为准。文字正文不小于 14px，按钮至少 44px 高；木纹与镂空不可降低文案对比度。

## 开发资产拆分清单（待风格确认后制作）

1. 木质外框、幕布、宣纸影幕、低对比背景装饰，分别独立图层。
2. 同一只举手兔皮影的透明底素材；实体与投影共用，分别调大小与透明度。
3. 月亮与独立光晕、少量金色微光。
4. 灯体与底座组合、轨道、拖动高亮、引导箭头。
5. 按钮底图和标签分开；所有文字用可排版文本，不依赖生成图内文字。

本轮不输出伪切图，也不把生成的整屏位图当成可玩页面。保存分享、图鉴、商店不属于首关。

## 评审检查

- 首眼能否看懂“让兔影碰月亮”和“只能拖灯”？
- 兔影和实体是否足够像同一只木偶，姿态是否一致？
- 三态角色、月亮、舞台是否一致，大小变化是否一眼可见？
- 手机尺寸下是否能读清文案，并轻松抓住灯把手？
- 风格通过后才制作可玩原型；静态稿不代表玩法验证通过。
